# Runners

Execute your properties.

## assert

Probably the most useful of all the runners provided within fast-check. This runner takes a property and executes it. By default, it throws automatically in case of failure. Thrown error is formatted to make it easily readable and actionable for the user.

Its signature can be summarized by:

```ts
function assert<Ts>(property: Property<Ts>, params?: Parameters<Ts>): Promise<void>;
```

:::tip
Check [`Parameters`](/docs/api/interfaces/Parameters) to run `assert` with advanced options.
:::

Resources: [API reference](/docs/api/functions/assert).  
Available since 0.0.1.

### Run details

Handle the `RunDetails` value directly in a plugin's `onAllRunsComplete` callback. Throw an error to report a failure, or return nothing when the outcome is acceptable. Set `noDefaultPlugins: true` to drop and replace the default report of `assert` with your own reporting:

```js
await fc.assert(property, {
  noDefaultPlugins: true,
  plugins: [
    () => ({
      onAllRunsComplete(out) {
        if (out.failed) {
          throw new Error(`Property failed after ${out.numRuns} tests`, {
            cause: out.errorInstance,
          });
        }
      },
    }),
  ],
});
```

The default reporter throws when `failed` is `true` and ignores other outcomes.

| Reason                   | `failed` | `interrupted`  | `counterexample`/`counterexamplePath` | `errorInstance`      |
| ------------------------ | -------- | -------------- | ------------------------------------- | -------------------- |
| failure of the predicate | `true`   | `true`/`false` | _any value_                           | _the thrown value\*_ |
| too many skipped values  | `true`   | `true`         | `null`                                | `null`               |
| plugin setup failure     | `true`   | `false`        | `null`                                | _the thrown value\*_ |
| successful run           | `false`  | `true`/`false` | `null`                                | `null`               |

_\*For predicate or plugin failures, `errorInstance` is the value thrown by the predicate or plugin method. It could eventually be `null` if the code throws `null`._

:::info[Plugin reporting]
See the [custom reports](/docs/configuration/custom-reports/) guide.
:::

Resources: [API reference](/docs/api/type-aliases/RunDetails).  
Available since 0.0.7.

## sample

Certainly one of the most useful when attempting to create your own arbitraries. `sample` gives you a way to extract very quickly what would be the values generated by your arbitrary.

Its signature is:

```ts
function sample<Ts>(generator: Property<Ts> | Arbitrary<Ts>, params?: Parameters<Ts>): Promise<Ts[]>;
```

Example of usage:

```js
const values = await fc.sample(fc.nat(), { numRuns: 10 });
// equivalent to:
// >  const wrappedValues = await fc.sample(
// >    fc.property(fc.nat(), predicate),
// >    { numRuns: 10 }
// >  );
// >  const values = wrappedValues.map(([value]) => value);
```

:::note
With a shrink path, `sample` returns all shrunk values at that level starting from the path. Pass `numRuns` directly in `sample`'s parameters (not via global configuration) to cap the number of returned values.
:::

Resources: [API reference](/docs/api/functions/sample).  
Available since 0.0.6.

## statistics

When building a new arbitrary, knowing what would be the generated values is a thing but checking how well they cover the range of possible values is also crucial in some cases. `statistics` can be seen as a refinement over `sample`. It helps users to properly design their own arbitraries and check how efficient they will be.

Its signature is:

```ts
function statistics<Ts>(
  generator: Property<Ts> | Arbitrary<Ts>,
  classify: (v: Ts) => string | string[],
  params?: Parameters<Ts>,
): Promise<Map<string, number>>;
```

Example of usage:

```js
const stats = await fc.statistics(
  fc.string(), // source arbitrary
  (v) => `${v.length} characters`, // classifier
  { numRuns: 100_000 }, // extra parameters
);
fc.defaultStatisticsLogger(stats);
// Possible output:
// >  0 characters...9.65%
// >  2 characters...9.56%
// >  1 characters...9.41%
// >  3 characters...9.30%
// >  6 characters...9.04%
// >  9 characters...8.92%
// >  7 characters...8.90%
// >  8 characters...8.90%
// >  10 characters..8.86%
// >  4 characters...8.79%
// >  5 characters...8.68%
```

`statistics` runs through the same runner as `sample` and `assert`, including plugins, and must be awaited. It returns a map from category labels to unrounded percentages of the values actually sampled, without logging. Values can belong to zero or more categories, so percentages do not necessarily sum to 100. With a shrink path, it classifies the same values as `sample`; pass `numRuns` locally to cap the number of sampled values.

To keep the previous log format, pass the result to `defaultStatisticsLogger`. It sorts categories by descending percentage, rounds to two decimal places, and logs one line per category. A custom logger can be passed as the second argument:

```js
fc.defaultStatisticsLogger(stats, (line) => customLogger(line));
```

When migrating, replace numeric run counts with `{ numRuns }` and remove `logger` from runner parameters and global configuration.

Resources: [API reference](/docs/api/functions/statistics), [default logger](/docs/api/functions/defaultStatisticsLogger).

Available since 0.0.6.
