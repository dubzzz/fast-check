# Runners

Execute your properties.

## assert

Probably the most useful of all the runners provided within fast-check. This runner takes a property and executes it. By default, it throws automatically in case of failure. Thrown error is formatted to make it easily readable and actionable for the user.

Its signature can be summarized by:

```ts
function assert<Ts>(property: Property<Ts>, params?: Parameters<Ts>): Promise<void>;
```

:::tip
Check [`Parameters`](/docs/api/interfaces/Parameters) to run `assert` with advanced options.
:::

Resources: [API reference](/docs/api/functions/assert).  
Available since 0.0.1.

### Run details

Handle the `RunDetails` value directly in a plugin's `onAllRunsComplete` callback. Throw an error to report a failure, or return nothing when the outcome is acceptable. Set `noDefaultPlugins: true` to drop and replace the default report of `assert` with your own reporting:

```js
await fc.assert(property, {
  noDefaultPlugins: true,
  plugins: [
    () => ({
      onAllRunsComplete(out) {
        if (out.failed) {
          throw new Error(`Property failed after ${out.numRuns} tests`, {
            cause: out.errorInstance,
          });
        }
      },
    }),
  ],
});
```

The default reporter throws when `failed` is `true` and ignores other outcomes.

| Reason                   | `failed` | `interrupted`  | `counterexample`/`counterexamplePath` | `errorInstance`      |
| ------------------------ | -------- | -------------- | ------------------------------------- | -------------------- |
| failure of the predicate | `true`   | `true`/`false` | _any value_                           | _the thrown value\*_ |
| too many skipped values  | `true`   | `true`         | `null`                                | `null`               |
| plugin setup failure     | `true`   | `false`        | `null`                                | _the thrown value\*_ |
| successful run           | `false`  | `true`/`false` | `null`                                | `null`               |

_\*For predicate or plugin failures, `errorInstance` is the value thrown by the predicate or plugin method. It could eventually be `null` if the code throws `null`._

:::info[Plugin reporting]
See the [custom reports](/docs/configuration/custom-reports/) guide.
:::

Resources: [API reference](/docs/api/type-aliases/RunDetails).  
Available since 0.0.7.

## sample

Certainly one of the most useful when attempting to create your own arbitraries. `sample` gives you a way to extract very quickly what would be the values generated by your arbitrary.

Its signature is:

```ts
function sample<Ts>(generator: Property<Ts> | Arbitrary<Ts>, params?: SampleParameters<Ts, 'arbitrary'>): Promise<Ts[]>;
function sample<Ts>(generator: Property<Ts>, params?: SampleParameters<Ts, 'property'>): Promise<Ts[]>;
```

Example of usage:

```js
const values = await fc.sample(fc.nat(), { numRuns: 10 });
// equivalent to sampling a property whose predicate always succeeds:
// >  const wrappedValues = await fc.sample(
// >    fc.property(fc.nat(), () => true),
// >    { numRuns: 10 }
// >  );
// >  const values = wrappedValues.map(([value]) => value);
```

:::warning Passing a property executes its predicate
By default, `sample` runs the predicate attached to the property. As such inputs rejected by call to `fc.pre(...)` are excluded from the returned array.

A failure of the predicate interrupts the sampling without shrinking or reporting the predicate error.

This behavior can be overridden by passing the parameter `noPredicateExecution: true` to `sample`. With that flagged toggled on, sampling will run without executing the predicate and this ignore runs rejected via `fc.pre(...)` and failed ones.
:::

:::note Shrink-path replay
When passed a `path` via its parameters, `sample` visits the shrunk values at that level starting from the path until the predicate fails or the candidates are exhausted. As with `assert`, `numRuns` does not cap shrink-path replay, whether configured locally or globally. Sampling an arbitrary or disabling the predicate visits all candidates at that level unless a plugin interrupts the run.
:::

Resources: [API reference](/docs/api/functions/sample).  
Available since 0.0.6.

## statistics

When building a new arbitrary, knowing what would be the generated values is a thing but checking how well they cover the range of possible values is also crucial in some cases. `statistics` can be seen as a refinement over `sample`. It helps users to properly design their own arbitraries and check how efficient they will be.

Its signature is:

```ts
function statistics<Ts>(
  generator: Property<Ts> | Arbitrary<Ts>,
  classify: (v: Ts) => string | string[],
  params?: StatisticsParameters<Ts, 'arbitrary'>,
): Promise<StatisticsResult>;
function statistics<Ts>(
  generator: Property<Ts>,
  classify: (v: Ts) => string | string[],
  params?: StatisticsParameters<Ts, 'property'>,
): Promise<StatisticsResult>;

interface StatisticsResult {
  counts: Map<string, number>;
  numValues: number;
}
```

Example of usage:

```js
const stats = await fc.statistics(
  fc.string(), // source arbitrary
  (v) => `${v.length} characters`, // classifier
  { numRuns: 100_000 }, // extra parameters
);
fc.defaultStatisticsLogger(stats);
// Possible output:
// >  0 characters...9.65%
// >  2 characters...9.56%
// >  1 characters...9.41%
// >  3 characters...9.30%
// >  6 characters...9.04%
// >  9 characters...8.92%
// >  7 characters...8.90%
// >  8 characters...8.90%
// >  10 characters..8.86%
// >  4 characters...8.79%
// >  5 characters...8.68%
```

`statistics` runs through the same runner as `sample` and `assert`, including plugins, and must be awaited. It returns `{ counts, numValues }` without logging: `counts` maps each category to its number of occurrences, and `numValues` is the number of values actually collected. Values can belong to zero or more categories, so the sum of the counts may differ from `numValues`. Repeated categories for the same value are counted each time.

When passed a property, `statistics` awaits its predicate before classifying the input. Skipped and interrupted inputs are excluded. Failing inputs are included, then collection stops without shrinking or reporting the predicate error. Pass `noPredicateExecution: true` to classify inputs without executing the property's predicate.

If the classifier throws, `statistics` reports a failed run, completes plugin cleanup, and rejects with the original thrown value. Disabling default reporting does not suppress classification errors.

With a shrink path, it classifies the same values as `sample`; `numRuns` does not cap shrink-path replay.

To keep the previous log format, pass the result to `defaultStatisticsLogger(stats)`. It calculates percentages using `numValues`, sorts categories by descending percentage, rounds to two decimal places, and logs one line per category to `console.log`. Pass a custom logging function as the second argument: `defaultStatisticsLogger(stats, logger)`. For custom formatting, use `stats.counts` and `stats.numValues` directly.

When migrating, replace numeric run counts with `{ numRuns }` and remove `logger` from runner parameters and global configuration.

Resources: [API reference](/docs/api/functions/statistics), [default logger](/docs/api/functions/defaultStatisticsLogger).

Available since 0.0.6.
